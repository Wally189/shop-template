Accessibility

Accessibility is part of the build.

House of Carol uses WCAG 2.2 AA as the internal quality baseline for public customer journeys, while recognising that conformance needs representative testing rather than a declaration from code alone.

What this site is designed to support

  • keyboard navigation with visible focus;
  • semantic headings, landmarks, lists, controls and form labels;
  • responsive reflow down to 320 CSS pixels without requiring horizontal page scrolling for core content;
  • text enlargement and zoom without hiding essential content or actions;
  • contrast and meaning that do not depend on colour alone;
  • reduced-motion preferences;
  • clear form instructions and feedback.

Current assurance state

Static accessibility checks and responsive source design are part of the contained build. A production release should additionally include representative keyboard, real-device and assistive-technology testing of the exact deployed version. An automated scan alone is not sufficient evidence.

Known preview limitation

The site is still a contained preview and the final production contact route is not configured. Once a verified accessibility contact route exists, it will be published here so barriers can be reported and handled through the website complaint/accessibility process.

If something prevents access

House of Carol's policy is to classify the barrier, provide a practical alternative where possible, correct material defects and update this statement when a known issue materially affects users.
