Accessibility

Accessibility is part of the build.

House of Carol uses WCAG 2.2 AA as the quality baseline for public customer journeys, while recognising that conformance requires representative testing rather than a declaration from code alone.

What this site is designed to support

  • keyboard navigation with visible focus;
  • semantic headings, landmarks, lists and controls;
  • responsive reflow to 320 CSS pixels without horizontal page scrolling for core content;
  • text enlargement and zoom without hiding essential content or actions;
  • contrast and meaning that do not depend on colour alone;
  • reduced-motion preferences;
  • plain link and button behaviour that remains understandable without decorative interaction.

Current assurance state

Accessibility is designed into the contained build. Before commercial release, the exact deployed version should additionally be checked by keyboard, on representative real devices, at 200% text enlargement and with appropriate assistive-technology testing. An automated scan alone is not sufficient evidence.

Known preview limitation

The site is still a contained preview and the final production contact route is not configured. Once a verified accessibility contact route exists, it will be published here so barriers can be reported and handled.

If something prevents access

House of Carol's approach is to identify the barrier, provide a practical alternative where possible, correct material defects and update this statement when a known issue materially affects users.
